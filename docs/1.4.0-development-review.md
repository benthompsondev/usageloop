## What made this release worth doing

| Priority | Evidence | Decision |
| --- | --- | --- |
| 1. Find updates | Updates was below the schedule in Settings, separated from About's version information. | Move the existing panel to the top of About. Keep one updater and all its signals. |
| 2. Reach the next action | Release notes preceded Download, and the model-support shortcut hard-coded Settings. About can also retain a deep scroll position. | Put actions before notes; route the shortcut to About; return About to the top. |
| 3. Keyboard access | Qt's focus chain includes the scroll container, and reparenting can reset a tab chain. | Set About-to-update tab order after installing the central widget. Test activation with the keyboard. |
| 4. Upgrade from the current release | The existing Windows matrix stopped at 1.3.8; users now have 1.3.9. | Add 1.3.9 to the same acceptance procedure. Actual execution awaits candidate CI. |

The less obvious improvement is preserving the user's next action after page
navigation and long release notes. It removes an extra search through the page
without adding background checks or another updater.

This is a navigation and update-discovery release. There is no evidence here
for changes to request execution, scheduling, model selection or quota policy.
Issue #2 needs its reporter's diagnostics before any cause-specific change.

## Languages

The initial scope deferred expansion because the public feedback did not
establish demand beyond English and Chinese. The owner then explicitly expanded
1.4.0 to include Spanish, Brazilian Portuguese, French and Japanese. All six are
now selectable, with persisted restart-based selection and English fallback.
There is no locale telemetry, and none was added.

Each translated catalogue has 567 matching English source keys. Coverage,
placeholders, dialogs, date/time controls and rendered layouts are checked across
all six languages. New catalogues are ordinary Python modules with automatic
packaging discovery. See the [multilingual validation record](1.4.0-multilingual-validation.md)
and [contributor guide](LOCALIZATION.md).

[PR #4](https://github.com/benthompsondev/usageloop/pull/4) describes the original
Chinese text as generated, then reviewed and tried by its contributor on Windows.
That does not establish an independent native-language review. The new Chinese
copy in this branch and all four new catalogues are generated and have not had native review.
Placeholder checks and rendered screenshots verify structure and display, not
the quality of every translation. A native review remains useful before release.

## Current technical references

Checked the official Qt for Python documentation through Context7:

- [QWidget ownership and tab order](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QWidget.html):
  changing window parents can append widgets to a new focus chain. Set the
  explicit tab link after the central widget has its final parent.
- [QScrollArea](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QScrollArea.html):
  a scroll area's current position persists independently of the stacked page.
  About explicitly returns its scrollbar to zero when opened.

## Verification

- Final regression: **622 tests run, 11 skipped**, compilation and both
  command-line help checks passed. The new tests failed on the old placement,
  shortcut and scroll behavior, then passed after the change.
- The update layout tests cover English/Chinese and Windows/Linux host surfaces
  at 720×560, 1024×768, 1280×720, 1366×768, 1600×900 and 1920×1080. They measure
  the installed version, status and action in idle, available, verified and
  error states, including long synthetic notes. Keyboard activation, manual-only
  checks, one panel, navigation persistence and the model-support route pass.
- Existing checksum, URL validation, installer confirmation, exit-on-install,
  Linux update and request-safety regressions pass as part of the suite.
- Native Windows captures from the real Qt widgets use temporary state and a
  synthetic provider. The harness also isolates language preferences, including
  interactive changes, from the installed app. Both language sets and both host surfaces were rendered
  at all six sizes. The Linux surface here is rendered on Windows, not on a
  Linux desktop.
- Local PyInstaller Windows executable built with file/product version 1.4.0.
  Its provider-free packaged activation check passed first launch, background
  no-pop and normal-launch restore. This check uses a small activation window;
  it does not exercise the full packaged MainWindow.
- English and Chinese interactive source previews also opened on About with
  automation off, temporary state/preferences and blocked external operations.
  Their update response is simulated. The installed 1.3.9 app was not changed.
- PSScriptAnalyzer reports no errors and four existing function-naming warnings
  in the install verifier. The same four warnings occur on the base version;
  adding 1.3.9 introduces no new warnings.

## Before a release candidate can ship

1. Review this local branch and authorize publication. Then run Windows/Linux CI
   builds and the complete install matrix, including the new 1.3.9 upgrade case.
2. Verify the actual Windows installer and full packaged UI in a disposable
   environment. Inno Setup and a disposable Windows environment are unavailable
   here; the installed application was not used for these checks.
3. Verify the packaged UI, updates and tray/window behavior on a real Linux
   desktop. No usable Linux desktop or package runtime is available here.
4. Review the new translated copy with native speakers where available. The
   six requested languages are implemented; no further expansion is planned.

The code is ready for review and candidate CI. These local results are not a
claim that the installer, upgrade or Linux desktop checks have already passed.
Do not install a development build over the normal app or publish different
bits under a version that has already been installed as a candidate.
