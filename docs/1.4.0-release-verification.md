# 1.4.0 release verification

The final pass started from `e05ac3a` on `codex/v1.4.0-about-updates`, based on
main `b782a69`. Published 1.3.9 and hefengq's merged localization history remain
intact. Publication means pushing the candidate and opening its PR. Merging and
publishing a release require a separate approval.

The corrected candidate passed 625 local unittest tests with 11
platform/environment skips, plus compilation. All nine multilingual tests also
passed on native Windows Qt with no skips. A rebuilt Windows executable passed
the six-language packaged acceptance on the native Windows backend, including
Japanese glyph shaping. These local checks used temporary synthetic data and
did not modify the installed application or send a Codex request.

## Focused corrections

- Independent automated linguistic review checked Spanish, Brazilian Portuguese,
  French and Japanese, prioritizing uncertain starts, no retry, quota, privacy,
  scheduling and installation. Japanese used "powered on" for "awake" in three
  strings and the short guide. It now explicitly excludes sleep. The French
  first-start action now includes "maintenant". Placeholders remain intact.
  This is automated review, not native-speaker or professional validation.
- Linux's default install confirmation described a Windows setup window.
  It now gives the target version and the existing translated Linux
  archive/checksum/restart explanation. No install operation changed.
- The intermittent Windows Qt IPC crash reproduced without the UI tests.
  Four IPC tests repeated in one process crashed within two batches. Keeping
  channels alive prevented the crash for 20 batches; forcing deferred cleanup
  brought it forward. A new collection/connection regression crashed the old
  code with an access violation. Replacing the two socket-capturing signal
  callbacks with decorated bound slots passed that regression and the focused
  IPC suite. The equivalent isolated probe passed 20 batches, 80 tests.
  These results support an object-lifetime fault at the Python/Qt boundary;
  they do not identify a particular upstream Qt defect. Mutex ownership,
  activation framing and request safeguards are unchanged.

## Packaged acceptance

The hidden `--ui-acceptance OUTPUT_FOLDER` path returns before production
providers, process locks, default app state or startup registration are created.
It constructs the real MainWindow with a synthetic provider and updater,
temporary state/history and an INI-backed language preference. It captures:

- Dashboard, Settings and About at 720x560 and 1366x768 in all six languages;
- a manually requested synthetic update and the actual install confirmation;
- saved language selection without changes to active or saved automation and
  scheduling settings, English fallback and Japanese glyphs where fonts exist.

Source tests explicitly reject production provider, state, process-lock or
startup-manager construction on this path. The Windows installer matrix invokes
the installed executable after fresh installation and upgrading from 1.3.9.
The latter verifies enabled automation, settings and history bytes and the
separate Chinese language preference before disabling only the synthetic
automation fixture for normal shortcut relaunch. It verifies the downloaded
published 1.3.9 installer's SHA-256 first. Other scenarios preserve automation off.

Linux package CI installs/uninstalls in temporary XDG directories, validates the
desktop file, then opens the built executable under Xvfb using Qt's xcb backend
and Noto CJK. JSON reports and screenshots are uploaded as Actions artifacts.
This is actual Linux packaged Qt rendering, not a Windows-rendered Linux label.
It does not prove a real desktop session's tray, notifications, Wayland or
display scaling. Windows CI uses offscreen rendering; native Windows checks
separately cover installed system fonts and Japanese shaping.

## Release assets and updater contract

The stable downloads remain on published 1.3.9 until 1.4.0 is released. Do not
point users at nonexistent 1.4.0 assets. The new stable release must contain:

```text
UsageLoop-Setup.exe
UsageLoop-Setup.exe.sha256
UsageLoop-1.4.0-linux-x86_64.tar.gz
UsageLoop-1.4.0-linux-x86_64.tar.gz.sha256
```

Version metadata is 1.4.0. Keep the Windows names stable for the existing 1.3.9
updater. Checksum files must name their matching payload and contain its SHA-256.
Before publication, use successful Windows/Linux artifacts built from the final
merged main commit. Revalidate the four downloads and the public latest-release
endpoint after publication; a candidate PR cannot prove those future endpoints.
Keep the release credit to hefengq. The existing installer remains unsigned, so
the current SmartScreen and checksum instructions still apply.

The final PR and its Actions checks are the current CI record. Source, packaged
UI, installer migration and desktop integration are distinct evidence. Passing
one does not imply that the others ran.
