# 1.4.0 expanded language candidate

Local work continues from `26b7c8d` on `codex/v1.4.0-about-updates`. At the start
of this expansion, GitHub main was still `b782a69`, latest stable was 1.3.9, and
there were no open PRs. No 1.4.0 publication workflow was started.

## What is included

All six requested languages are selectable: English, Simplified Chinese,
Spanish, Brazilian Portuguese, French and Japanese. The system option resolves
to a supported language or English. Every translated catalogue has the same
567 source keys. Selection persists in Qt settings independently of scheduling
and takes effect on full exit/restart. The CLI remains English.

The four new catalogues are generated, checked against the intended safety
meaning, and tested technically. They have **not** had native-language or
professional localization review. The original Chinese contribution was
generated and tried by its contributor on Windows; later additions also lack
independent native review. Tests establish coverage and behavior, not fluency.

The catalogues retain the distinction between a current running window and an
earlier unconfirmed start. They preserve no-retry warnings, existing quota
limits, weekly protection, read-only Sync, manual updates, verified downloads,
Windows setup and Linux managed/manual installation instructions. Technical
summaries, commands, model IDs, paths and internal states remain untranslated.

Languages are ordinary English-keyed dictionaries under `src/sentinel/locales/`;
the existing Chinese dictionary remains in place. There is no translation
service, new dependency, positional message indexing or runtime generation.
New strings must be added to every catalogue. See [contributor guidance](LOCALIZATION.md)
and the [translated quick guide](MULTILINGUAL_GUIDE.md).

## Layout and fonts

Native checks found clipped schedule buttons at 720 pixels in English and the
longer Latin translations. Below 1000 pixels, the dashboard/About/Settings cards,
weekly quick groups and individual-day editors now stack. At normal width they
retain their existing columns. Weekly metric labels wrap. This changes layout,
not saved times, schedule decisions or automation.

English retains AM/PM. Chinese and the four new languages use 24-hour controls,
preserve `00:00`, and use numeric date patterns. Widget locales never change
the process locale used by the scheduler. Japanese uses system font fallback.
Native Qt text shaping verified nonzero glyphs for Japanese safety terms,
including characters missing from the primary font but supplied by fallback.
Linux CI installs Noto CJK; minimal Linux desktops also need an appropriate font.
The application does not download fonts.

## Evidence

- Full candidate regression: **622 tests, 11 skips**, all remaining tests pass.
  Compilation and CLI/desktop `--help` checks pass. The additional Windows
  offscreen font skip is covered by a separate native Japanese glyph check.
- **Nine native Windows multilingual tests pass without skips.** They cover
  all six languages, both host surfaces, actual 720×560 and 1366×768 window
  sizes, dashboard/Settings/About, daily/expanded weekly controls, button text
  bounds, translated day names, dialog labels, midnight, persistence across
  processes, unknown-text fallback, and unchanged automation/settings.
- Update layout regressions cover every language and both host surfaces at six
  sizes, including idle/available/error/verified states and keyboard navigation.
  Status tests preserve decision kind, severity and manual-start visibility.
- Catalogue checks enforce matching key sets, nonempty values, duplicate-key
  detection, literal/conditional-call coverage and placeholder/format parity.
- Windows executable builds and provider-free packaged activation pass. The
  frozen archive contains `sentinel.locales.es`, `.pt_BR`, `.fr`, `.ja` and
  `sentinel.translations`, establishing that the catalogues ship in the bundle.
  Activation checks use the small provider-free window; full packaged MainWindow
  and installer acceptance remain separate release gates.
- Native screenshots cover all six languages at minimum/normal sizes, the
  translated Qt confirmation dialog, history and update states. Linux-labelled
  surfaces were rendered on Windows, not on a Linux desktop.

An initial full run terminated without a Python test summary inside an unchanged
Qt single-instance test. A clean export of `26b7c8d` passed its 613 tests, and
the expanded candidate subsequently passed with Python fault reporting enabled.
No single-instance or scheduler patch was made. The cause of that initial
termination is unestablished; it is recorded rather than presented as fixed.
Candidate CI and packaged activation remain required checks.

## Remaining release gates

The local code and translations are complete for review. Before publication,
run candidate Windows/Linux CI and the Windows 1.3.9 upgrade matrix, then check
the actual Windows installer/full packaged UI and a genuine Linux desktop.
Inno Setup is unavailable locally. WSL lists only Docker's internal distribution,
and the Docker Linux engine is not running, so no Linux build or desktop pass
is claimed. Native-language copy review is recommended before stable publication;
there is no claim that it has already happened.

The conservative clock verifier, request submission, quota decisions, history
and scheduling modules are unchanged. No installed application/settings were
modified, no live Codex request was initiated, and no branch or release was
published. Approval is still required before publishing the expanded candidate.
