Codex window timing

When does the Codex 5-hour window start?

On accounts that expose a five-hour window, UsageLoop has observed the next reset clock becoming fixed after the first request starts a new window. Reaching the previous reset time alone does not necessarily start another countdown.

Reviewed October 29, 2026. Based on observations recorded while developing UsageLoop and the 1.4.0 application's behavior. No live request was made for this article. These observations are not an OpenAI guarantee; account limits and behavior can change.

Starting earlier does not add quota or bypass a limit. The start is a normal Codex request and uses subscription allowance. If your account shows no five-hour window, this scheduling approach does not apply.

A moving estimate versus a running clock

Before a window starts, repeated read-only observations can show a reset roughly five hours ahead that keeps moving forward. UsageLoop calls that unanchored. A single future reset timestamp is not enough to establish that a countdown is running.

After a window starts, repeated observations can show the same future reset time. UsageLoop calls that anchored. Its countdown can then run toward that time. Delays, stale observations and clock differences can complicate confirmation.

What an earlier start changes

  1. 1:00 AM: the old window ends. In this example, no new request arrives yet.
  2. 4:00 AM: a small scheduled request starts the next normal window.
  3. 7:00 AM: you begin work. The clock has already run for about three hours.
  4. Around 9:00 AM: that window resets, rather than around noon if its first request had been at 7:00 AM.

This is an illustration, not a promised reset time. You can work at 7:00 AM in either case if allowance remains. Starting early only changes when the next normal reset is expected; the start itself consumes some allowance.

Check your own account first

  1. Open Codex's usage view and check whether your account actually has a five-hour limit. In the CLI, /status shows session and rate-limit information when available. OpenAI's usage documentation links to the current usage dashboard.
  2. In UsageLoop 1.4.0, use Sync usage to refresh usage observations. Sync is read-only and sends no model request. A failed refresh leaves the last-known information; it does not make stale values current.
  3. Read the current clock and Recent starts separately. A running clock describes the window now. A confirmed start is UsageLoop's conservative assessment of a particular attempt.

A running window does not prove UsageLoop started it. Another Codex session can start the window. If an earlier attempt remains unconfirmed, UsageLoop preserves that outcome and does not automatically retry it. Do not repeat an uncertain send just to obtain a confirmed label. See the confirmation limitation and controlled counterexample.

The weekly limit is separate

A five-hour reset does not reset a weekly allowance. OpenAI documents shared usage allowances and says weekly limits may also apply. UsageLoop displays last-known weekly information and blocks automatic starts when the weekly allowance is nearly exhausted. It cannot change those limits. Check the current official usage guidance for your plan.

Scheduled starts are not banked resets

UsageLoop does not redeem banked Codex resets or buy credits. It sends a small request only when the next normal window is eligible to start. It cannot end an active window early or replenish weekly quota. For that separate account feature, use OpenAI's banked-reset explanation.

When a scheduled command is enough

A small Codex command in cron or Windows Task Scheduler may already do what you need. UsageLoop adds pre-send window and weekly-allowance checks, no automatic retry after an uncertain send, and a visible record of the result. It runs on Windows and Linux, requires Codex already signed in, and needs the computer awake with the app running. It cannot send while the computer is off or asleep.

See UsageLoop's downloads and installation requirements, or keep your existing command if it already meets your needs.
